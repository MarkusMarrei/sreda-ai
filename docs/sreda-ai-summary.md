## 1. Философия и фундаментальная концепция

### Главная проблема индустрии
Существующие решения в Open-Source ИИ разделены на две бесперспективные крайности для 90% рядовых пользователей:
1. **Тяжелые монолиты** (*ComfyUI, Text-Generation-WebUI, Automatic1111*), требующие 16–24 ГБ дискретной VRAM (NVIDIA RTX 3090/4090) и гигабайты зависимостей PyTorch/CUDA. На ноутбуках и офисных ПК они приводят к падению системы (OOM / Blue Screen / Driver Timeout).
2. **Изолированные текстовые чаты** (*LM Studio, Ollama, Jan*), умеющие запускать только одну текстовую модель, полностью игнорируя автономное зрение, распознавание речи, нейроозвучку, генерацию картинок и живой RAG в едином контуре.

### Концепция SREDA AI
**SREDA AI — это сверхэффективная мультимодальная агентская рабочая станция, специально спроектированная для работы на потребительских и ультрабюджетных системах с интегрированной графикой (APU/UMA: AMD Radeon 780M/680M, Intel Iris Xe/Arc, слабые дискретные GPU).**

Вместо одной неподъемной мультимодальной нейросети на 70 млрд параметров система использует **микро-оркестрацию специализированных легковесных субмоделей**, каждая из которых решает узкую задачу с минимальным расходом ресурсов.

## 2. Аппаратные ограничения и специфика Windows UMA/RAM

### 2.1. Проблема расхода памяти в APU-архитектурах
В системах с APU (например, AMD Ryzen 7 7840HS / 8840HS со встроенным ядром Radeon 780M) **физическая видеопамять (VRAM) не изолирована** — она динамически аллоцируется из общей оперативной памяти (UMA — Unified Memory Architecture).

* **Симптом:** Когда ОС Windows 10/11 работает в стандартном режиме, системный кэш (Standby List / Working Set) разрастается на 6–10 ГБ. При попытке запустить квантованную модель на 4–8 ГБ через Vulkan драйвер видеокарты AMD запрашивает память у ОС, сталкивается с отказом аллокации и падает с ошибкой `VK_ERROR_OUT_OF_DEVICE_MEMORY`.
* **Что не сработало (Ошибочный подход):** Попытка принудительно убивать процессы браузеров или системные службы. Это вызывало гнев пользователей, нестабильность Windows и конфликт с системным драйвером AMD.

### 2.2. Сервис оптимизации SREDA Boost: что сработало
Решение было найдено в реализации сервиса **SREDA Boost** (`backend/boost_service.py`):
1. **Компактизация Working Set через Win32 API:**
   Использование системного вызова Windows `kernel32.SetProcessWorkingSetSize(hProcess, -1, -1)` (EmptyWorkingSet). Функция безболезненно сбрасывает неиспользуемые страницы памяти фоновых процессов в файл подкачки, высвобождая от 800 МБ до 2.5 ГБ физической ОЗУ непосредственно перед инициализацией `llama-server`.
2. **Приоритезация вычислительного ядра:**
   Принудительный перевод процесса `llama-server.exe` в класс приоритета `HIGH_PRIORITY_CLASS` (`0x00000080`). Это гарантирует, что фоновые системные прерывания Windows не вызывают просадку скорости генерации (токенов в секунду).
3. **Строгий Whitelist безопасности:**
   Критически важный опыт: функции оптимизации обязаны содержать черный список исключений. Ни при каких обстоятельствах нельзя сбрасывать или замедлять:
   - Драйверы AMD: `amdfendrs.exe`, `radeonsoftware.exe`, `amdow.exe`.
   - Драйверы NVIDIA: `nvcontainer.exe`, `nvdisplay.container.exe`.
   - Драйверы Intel: `igfx*.exe`, `arccontrol.exe`.
   - Системные процессы ядра Windows: `csrss.exe`, `dwm.exe`, `lsass.exe`, `services.exe`, `explorer.exe`.

### 2.3. Алгоритмы расчета совместимости по RAM в Hugging Face Hub
* **Проблема (Баг «undefined ГБ» и ложные предупреждения):**
  В ранних итерациях поиск моделей на Hugging Face сравнивал размер скачиваемого GGUF с *сиюминутной свободной оперативной памятью* (`available_ram_gb`). Если на ПК с 16 ГБ ОЗУ в момент поиска было свободно всего 900 МБ (например, открыт Photoshop или браузер), то даже модель размером 0.7 ГБ (Gemma 1B) помечалась красным бейджем: `⚠ Превышает RAM`. Более того, если размер файла находился в LFS-метаданных Hugging Face (`item['lfs']['size']`), а не в корневом ключе `size`, размер определялся как `None`, что приводило к отображению надписи `undefined ГБ`.
* **Правильное архитектурное решение (`backend/hf_hub.py`):**
  1. Извлечение размера обязано проверять LFS:
     ```python
     size = item.get("size")
     if size is None or size == 0:
         lfs = item.get("lfs")
         if isinstance(lfs, dict):
             size = lfs.get("size", 0)
     size = int(size) if size else 0
     ```
  2. Оценка совместимости должна опираться на **общую физическую память системы (Total RAM)**, так как SREDA Boost освободит память перед стартом:
     - `размер * 1.25 <= Total_RAM * 0.70` ➔ `recommended` (зеленый бейдж «Совместимо»);
     - `размер * 1.25 <= Total_RAM * 0.90` ➔ `warning` (желтый бейдж «Высокая нагрузка»);
     - `размер * 1.25 > Total_RAM * 0.90` ➔ `not_recommended` (красный бейдж «Превышает RAM»).

## 3. Оркестрация субмоделей: паттерн «Разделение труда»

### 3.1. Почему монолитные мультимодальные LLM терпят крах на слабых ПК
Попытка запустить сквозную мультимодальную модель (например, LLaVA 7B/13B или Qwen-VL) на интегрированной видеокарте с 16 ГБ общей памяти приводит к:
1. Огромному потреблению VRAM на этапе энкодера изображений (CLIP / SigLIP съедают 2–3 ГБ сверх самой LLM).
2. Замедлению текстовой генерации до 1–2 токенов в секунду.
3. Невозможности добавить синтез речи или генерацию изображений без выгрузки всей модели из памяти.

### 3.2. Архитектура компьютерного зрения (ViT-GPT2 через ONNX Runtime)
* **Реализация (`backend/vision_service.py`):**
  Используется связка Vision Transformer (ViT) и квантованного GPT-2 декодера (`vit_encoder_quantized.onnx` + `gpt2_decoder_quantized.onnx`).
* **Почему это эффективно:**
  - Исполняется через `onnxruntime` на CPU (`CPUExecutionProvider`) с нулевым расходом драгоценной VRAM видеокарты.
  - Анализ изображения занимает 400–800 миллисекунд.
  - На выходе формируется компактный текстовый анализ (описание сцены, ключевые объекты, цветовая гамма, текст), который инжектируется в системный промпт LLM в тегах `[USER_IMAGE_ANALYSIS]`. Основная LLM рассуждает об изображении так, будто видит его нативно.

### 3.3. Архитектура речевого тракта (Whisper STT + Piper TTS)
* **Speech-to-Text (`backend/audio_service.py`):**
  - Используется компактный C++ бинарник `whisper-cli.exe` на базе модели `ggml-tiny.bin` (всего 75 МБ).
  - Никаких тяжелых Python-библиотек PyTorch/Transformers в рантайме микрофона. Запись аудио сжимается в WAV и расшифровывается за 200–300 мс.
* **Text-to-Speech:**
  - Используется легковесный C++ движок `piper.exe` и ONNX-модели голосов (`ru_RU-dmitri-medium`, `ru_RU-irina-medium`, `en_US-lessac-medium`).
  - Размер одного голоса — ~60 МБ.
  - Генерация речи идет с фактором реального времени 0.15x (фраза генерируется быстрее, чем длится звук).

### 3.4. Архитектура графики (SDXS-512 через Vulkan sd-cli)
* **Реализация (`backend/multimedia_orchestrator.py`):**
  - Модель: **SDXS-512** (дистиллированная 1-step диффузия в квантовании `Q8_0 GGUF`, ~650 МБ).
  - Бинарный движок: `sd-cli.exe` с поддержкой Vulkan.
  - Время генерации картинки 512x512: всего 1.5–3 секунды на встроенной графике Radeon 780M без перегрузки видеопамяти.

### 3.5. Текстовое ядро (llama-server + Vulkan + Flash Attention)
* **Флаг `-fa on` (Flash Attention):**
  Критически обязателен при запуске `llama-server.exe`. Экономит до 40% VRAM на длинных контекстах (4096–8192 токена) и предотвращает квадратичный рост расхода памяти при обработке больших документов RAG.
* **Тернарные квантования (Bonsai 2 PTQ1_0 / Gemma):**
  Позволяют моделям уровня 9B и 4B работать на скорости 15–30 токенов/сек на потребительском «железе».

## 4. Гибридная облачная интеграция (Zero-VRAM Mode)

Когда пользователю требуются глубокие рассуждения (модели 70B–671B) или когда локальная память полностью занята, станция активирует режим **Zero-VRAM Mode**:

### 4.1. Сбер GigaChat: подводные камни
* **Сертификаты Минцифры РФ:**
  Python-библиотека `requests` по умолчанию использует стандартное хранилище Mozilla CA, где нет российских доверенных корневых сертификатов, из-за чего запросы к `ngw.devices.sberbank.ru` падали с `SSLCertVerificationError`.
  *Решение:* Включение автоматической загрузки сертификата Минцифры либо безопасная опция верификации в `backend/provider_service.py`.
* **Авторизация:**
  Поддержка как прямой пары `Client ID` + `Client Secret`, так и готовой строки `Authorization: Basic <base64>`. Автоматическое кэширование OAuth-токена доступа на 29 минут.

### 4.2. OpenRouter и OpenAI-совместимость
* Предоставляет доступ к флагманам `DeepSeek V3`, `DeepSeek R1`, `Claude 3.5 Sonnet`, `Llama 3.3 70B`.
* Радар состояния инференса в заголовке окна мгновенно переходит в режим `Cloud / 0 MB VRAM`, освобождая локальный движок `llama-server` от нагрузки.

## 5. Фронтенд, UI/UX и интернационализация (9 языков)

### 5.1. Баг «залипания / некликабельности» кнопок и его исправление
* **Симптом:** Пользователь жаловался: *«Слушай, опять вернулся баг, при котором кнопки не нажимаются»*.
* **Первопричина:**
  В сложных SPA при динамической перерисовке элементов списка (чаты, модели, RSS) разработчики часто вызывают повторную инициализацию слушателей событий (`initEventListeners()`), либо заменяют innerHTML контейнеров, теряя привязанные замыкания.
  Если на кнопку вешается `btn.addEventListener('click', handler)` внутри функций рендеринга, слушатели либо дублируются десятками раз (замораживая UI синхронными вызовами), либо удаляются при перезаписи DOM.
* **Правильное решение (Делегирование событий и идемпотентность):**
  1. Все статические кнопки (создать чат, открыть модалку, переключить движок) инициализируются **строго один раз** при старте приложения через `initEventListeners()`.
  2. Для динамических элементов списка (список моделей, результаты Hugging Face) слушатели назначаются непосредственно на создаваемый DOM-элемент в момент его создания (`btn.onclick = (e) => { e.stopPropagation(); action(); }`).

### 5.2. Баг наложения иконок модели (FontAwesome vs Child Elements)
* **Симптом:**
  При переключении моделей на экране появлялась красная микросхема, поверх которой накладывалась зеленая плашка с буквой `G` (GigaChat).
* **Первопричина:**
  Контейнер иконки в HTML был объявлен как `<i class="fa-solid fa-microchip" id="model-chip-icon"></i>`.
  Когда активировалась модель GigaChat, JS-код вызывал:
  `dom.modelChipIcon.innerHTML = '<span class="badge-g">G</span>';`
  Но класс `fa-solid fa-microchip` оставался на элементе `<i>`! В FontAwesome иконка рисуется через CSS-псевдоэлемент `::before { content: "\f2db"; }`.
  В результате браузер одновременно рендерил и микросхему через `::before`, и букву `G` через внутренний `<span>`.
* **Правильное решение:**
  1. В HTML иконка обернута в нейтральный `<span>`:
     ```html
     <span id="model-chip-icon" class="model-chip-icon">
       <i class="fa-solid fa-microchip" style="color: var(--accent-red)"></i>
     </span>
     ```
  2. Создана строгая функция `updateModelChipIcon(mode)`:
     - `mode === 'gigachat'`: рендерит *только* `<span class="badge-g">G</span>`;
     - `mode === 'api'`: рендерит *только* `<i class="fa-solid fa-cloud"></i>`;
     - `mode === 'local'`: рендерит *только* `<i class="fa-solid fa-microchip"></i>`.

### 5.3. Динамическая локализация состояний движка
* Поддерживаются **9 языков**: RU, EN, DE, FR, ES, PT, IT, JA, KO.
* Любое изменение состояния (кнопка в шапке «Запустить в движок» ➔ «Выгрузить», сообщения в радаре, тосты об удалении файла) обязано извлекать строку из словаря:
  ```javascript
  const dict = I18N[state.settings.language || 'ru'] || I18N.ru;
  btn.textContent = dict.btnActivate || 'Запустить в движок';
  ```
* Запрещено оставлять хардкод русскоязычных или англоязычных строк в динамических функциях!

## 6. Жизненный цикл процессов Windows и сетевой стек

### 6.1. Борьба с зомби-процессами и освобождение портов
* На Windows процессы `llama-server.exe`, запущенные через `subprocess.Popen`, при аварийном закрытии родительского Python-скрипта могут оставаться висеть в памяти как процессы-сироты, блокируя TCP-порты `8080` и `1234`.
* **Решение в `run.py`:**
  Перед запуском FastAPI сервер сканирует занятость портов через `netstat / powershell Get-NetTCPConnection` и принудительно завершает зависшие экземпляры `llama-server.exe` перед открытием сокетов.

### 6.2. Создание ярлыков Windows
* Использование скрипта `WScript.Shell` через PowerShell для создания ярлыка `SREDA AI.lnk` прямо на рабочем столе пользователя (`$env:USERPROFILE\Desktop`). Это исключает необходимость в тяжелых MSI-инсталляторах.

### 6.3. Git-безопасность и чистый репозиторий
1. В `.gitignore` внесены все персональные файлы конфигов (`backend/config/providers.json`), локальные базы и временные аудиозаписи.
2. Файлы документации и скриншоты в `docs/screenshots/**` явным образом исключены из игнорирования (`!docs/screenshots/**`).
3. Токены доступа GitHub никогда не сохраняются в файле `.git/config`: после выполнения пуша `remote origin` немедленно санитизируется до чистого URL `https://github.com/MarkusMarrei/sreda-ai.git`.

## 7. Свод правил и антипаттернов для ИИ-агентов (Agent Rules & Guidelines)

Если вы — автономный ИИ-агент, которому поручено доработать или отладить кодовую базу SREDA AI, **строго следуйте этим правилам**:

### 🚫 ЧТО ДЕЛАТЬ ЗАПРЕЩЕНО (Anti-Patterns):
1. **Не добавляйте тяжелые фреймворки в рантайм слабых задач:**
   Запрещено подключать `torch`, `torchvision`, `diffusers` или `transformers` для задач вроде озвучки, STT или распознавания изображений. Используйте только C++ бинарники (`whisper-cli`, `piper`, `sd-cli`) или легковесный `onnxruntime`.
2. **Не привязывайтесь к CUDA:**
   Архитектура построена на универсальном API **Vulkan**. Любой код инференса должен работать на AMD Radeon и Intel Arc без требований наличия драйверов NVIDIA.
3. **Не вешайте обработчики событий внутри циклов перерисовки DOM:**
   Это приводит к багу «некликабельных кнопок». Слушатели событий либо делегируются, либо устанавливаются строго в точке создания конкретного DOM-узла.
4. **Не модифицируйте `index.html` и `app.js` только в одной папке:**
   Проект имеет синхронную структуру: изменения обязаны параллельно вноситься и в каталог репозитория `GitHub/`, и в текущую рабочую версию `SREDA AI_v9/`.
5. **Не сохраняйте жестко заданные размеры экрана и путей:**
   Используйте `Path.resolve()` и системные переменные окружения (`USERPROFILE`, `LOCALAPPDATA`).

### ✅ ЧТО ДЕЛАТЬ ОБЯЗАТЕЛЬНО (Best Practices):
1. **Всегда вызывайте `SetProcessWorkingSetSize` перед стартом тяжелых моделей:**
   Освобождение памяти на Windows спасает графическое ядро Radeon/Intel от падений `VK_ERROR_OUT_OF_DEVICE_MEMORY`.
2. **Сохраняйте двуязычность документации:**
   Главный файл `README.md` пишется на чистом техническом английском языке для международного сообщества GitHub. Все изменения дублируются в `README_RU.md` на русском языке.
3. **Используйте безопасный парсинг данных Hugging Face:**
   Всегда проверяйте наличие ключа `lfs` при чтении размеров моделей из API Hugging Face.
4. **Защищайте системный белый список (Whitelist) процессов:**
   Ни при каких обстоятельствах не нарушайте работу драйверов дисплея AMD/NVIDIA/Intel.
